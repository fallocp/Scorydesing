# Fix: «Resolver texto» en ajustes sobre la diapositiva + popup que se cierra

- Bug 1, la causa: la regla que convierte el copy `pending` en `none` (es decir, conservar el texto) excluía cualquier plan con `design_source`. Cuando el planner elegía la propia diapositiva o otra como fuente (`adapt_layout`/`replicate`), el plan exigía texto literal. Además, con `copy_mode: none` y fuente, el generador recibía la orden «SIN TEXTO».
- Bug 1, el arreglo: hay una sola regla compartida, `keepsExistingText` en `_shared/desaing/conversationActions.ts`. La usan la reparación del planner (`explorationProvider.ts`) y el cliente (`useDesignConversation.ts`). Si el plan trabaja sobre el HTML actual, o sobre una fuente de diapositiva en modo `replicate` o `adapt_layout`, y no pide texto nuevo, el copy queda en `none` y el plan se ejecuta. En `designCanvasHtml.ts`, `none` con esa fuente ahora significa «SIN TEXTO NUEVO: conserva los textos del HTML». `style_only` y los diseños nuevos siguen pidiendo el texto.
- Bug 2, la causa: el popup no se cerraba por el commit 0711b43. Su estado abierto (`generatorOpen`) vive en el estado de `PresentationsPage`, así que cualquier remontaje o recarga de la página lo cerraba. 07c7242 sólo conservaba la diapositiva. No pude reproducir qué dispara el remontaje: puede ser HMR del dev server, un cambio de `activeBusinessId` (la página usa esa key) o una recarga.
- Bug 2, el arreglo: `activeSlideMemory.ts` recuerda en sessionStorage si el popup está abierto, por negocio y proyecto. `PresentationsPage.tsx` lo reabre al recargar el proyecto, con la diapositiva recordada y su sesión guardada, y lo olvida al cerrarlo. Sólo cubre proyectos guardados; un borrador sin guardar no se reabre.
- Archivos: `conversationActions.ts`, `explorationProvider.ts`, `designCanvasHtml.ts`, `useDesignConversation.ts`, `activeSlideMemory.ts`, `PresentationsPage.tsx`.
- Tests: casos nuevos en `explorationProvider.test.ts` (el pedido exacto con `adapt_layout`, `replicate` y `style_only`), `useDesignConversation.test.ts` (el mismo pedido sobre «Diapositiva original») y `activeSlideMemory.test.ts` (el popup se reabre tras remontar). Ajusté un test viejo de bloqueo para que use un diseño nuevo, porque sobre el HTML actual ya no se bloquea. Los 3 archivos pasan (184 tests).
- Verificación: `npm run type-check` ok; `deno check --no-lock` de `desaing-server` y `generate-design-html` ok. No quedan logs temporales.
- Redesplegar las dos funciones: `supabase functions deploy desaing-server` y `supabase functions deploy generate-design-html`.
