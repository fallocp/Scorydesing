# Campaign Architecture

This document describes the combinable campaign architecture that replaces the flat-branch model. It covers entity relationships, the dimension composition model, and data flow from configuration to AI-generated content.

## Overview

The architecture organizes campaigns into four layers:

1. **CampaignCategory** — Top-level tabs (e.g., "Xending Pagos / FX", "Produce / Agro")
2. **CommercialBranch** — Master commercial angles with strategic configs (e.g., "Velocidad - Mismo Día")
3. **IndustryVertical** — Combinable product/industry contexts (e.g., "Aguacate Michoacán")
4. **MarketMoment** — Temporal/event-driven triggers (e.g., "Fed", "Banxico")

Content is generated by **composing dimensions** — Branch + Vertical + Moment + Channel + Angle — rather than creating a separate branch for every combination.

## Entity Relationships

```
BusinessTenant
├── CampaignCategory (1:N)
│   ├── CommercialBranch (1:N) — each with StrategicConfig
│   ├── IndustryVertical (1:N) — combinable with any branch
│   └── MarketMoment (1:N) — temporal triggers
├── BusinessChannel (1:N) — distribution channels
├── BusinessAngle (1:N) — persuasion approaches
├── MasterPrompt (1:N, versioned) — brand voice
└── ComplianceRules (embedded JSONB) — forbidden terms, max values
```

All entities are scoped by `business_id`. Row-Level Security (RLS) policies enforce tenant isolation at the database level.

### Key Relationships

| Parent | Child | Relationship |
|--------|-------|-------------|
| `business_tenants` | `campaign_categories` | One business has many categories |
| `campaign_categories` | `commercial_branches` | One category contains many branches |
| `campaign_categories` | `industry_verticals` | One category contains many verticals |
| `campaign_categories` | `market_moments` | One category contains many moments |
| `business_tenants` | `master_prompts` | One business has many prompt versions |
| `business_tenants` | `business_channels` | One business has many channels |
| `business_tenants` | `business_angles` | One business has many angles |

### Uniqueness Constraints

- Branch slug is unique per `(business_id, category_id)`
- Category slug is unique per `business_id`
- Vertical/moment slugs are unique per `(business_id, category_id)`
- Channel/angle slugs are unique per `business_id`

## Combinable Generation Model

Instead of creating a branch for every combination (e.g., "Velocidad + Aguacate", "Velocidad + Mango"), the system composes dimensions at generation time:

```
┌─────────────────────────────────────────────────────┐
│              Combinable Generator                    │
│                                                      │
│  Branch (required)  ──┐                              │
│  Vertical (optional) ─┤                              │
│  Moment (optional)  ──┼──→ composePromptContext() ──→ AI │
│  Channel (required)  ─┤                              │
│  Angle (optional)   ──┘                              │
└─────────────────────────────────────────────────────┘
```

### Dimension Roles

| Dimension | Required | Source | Contributes |
|-----------|----------|--------|-------------|
| **CommercialBranch** | Yes | `commercial_branches.strategic_config` | Objetivo, insight, dolor, promesa, audiencia, claims, CTAs, visual guide |
| **IndustryVertical** | No | `industry_verticals.keywords`, `visual_context` | Product-specific keywords, visual cues |
| **MarketMoment** | No | `market_moments.trigger_type`, `description` | Temporal context, event triggers |
| **Channel** | Yes | `business_channels` | Format constraints (story, post, email, etc.) |
| **Angle** | No | `business_angles` | Persuasion approach (urgency, comparison, testimonial, etc.) |

### Composition Example

Selecting "Velocidad - Mismo Día" + "Aguacate Michoacán" + "Instagram Ads" + "Urgencia Operativa" produces a prompt that includes:

1. The business's **master prompt** (brand voice)
2. The branch's **strategic config** (objetivo: same-day payments, audiencia: produce exporters, etc.)
3. The vertical's **keywords** (aguacate, Michoacán, temporada, exportación) and **visual context**
4. The channel's format constraints (Instagram Ads dimensions)
5. The angle's persuasion approach (urgency-driven messaging)

This eliminates the need for a "Velocidad - Aguacate" branch, a "Velocidad - Mango" branch, etc.

## Data Flow: Config to AI Content

### 1. User Selects Dimensions

The UI presents category tabs → branch cards → optional vertical/moment selectors → channel/angle pickers. Selections are stored in the Zustand store.

### 2. Prompt Composition

The `composePromptContext()` function merges all dimension data:

```typescript
composePromptContext({
  masterPrompt: "Eres un copywriter para Xending...",
  strategicConfig: { objetivo: "...", audiencia: "...", ... },
  vertical: { keywords: ["aguacate", "Michoacán"], visual_context: "..." },
  moment: { trigger_type: "fed", description: "..." },
  channel: "Instagram Ads",
  angle: "Urgencia Operativa",
  brandIdentity: { name: "Xending", ... },
  complianceRules: { forbidden_terms: [...], ... },
  brandDisclaimer: "..."
})
```

### 3. Edge Function Call

The composed context is sent to the appropriate edge function:

- **`generate-ideas`** — Generates copy variants (headline, subcopy, CTA) or image descriptions
- **`generate-design-html`** — Generates Instagram Story HTML from approved copy + image
- **`branch-chat`** — Interactive brainstorming session with strategic context
- **`generate-strategy`** — Generates new branch proposals for a category
- **`refine-branch`** — Refines an existing branch based on feedback

### 4. AI Processing

Each edge function:
1. Fetches business context from DB via `fetchBusinessContext()` (master prompt, compliance rules, brand identity, channels)
2. Fetches entity-specific data (strategic config, vertical keywords, moment triggers)
3. Builds a system prompt combining all context
4. Calls the Anthropic API
5. Parses and returns structured results

### 5. Storage

Generated content is stored in `design_campaigns` and `design_pieces` with full dimension metadata:

```sql
-- Each campaign records which dimensions were used
design_campaigns.business_id      -- tenant scope
design_campaigns.category_id      -- which category
design_campaigns.commercial_branch_id  -- which branch
design_campaigns.vertical_id      -- which vertical (nullable)
design_campaigns.moment_id        -- which moment (nullable)
design_campaigns.channel          -- which channel
design_campaigns.angle            -- which angle (nullable)
```

## Multi-Tenant Isolation

Every entity table has a `business_id` FK to `business_tenants`. RLS policies ensure:

- Users can only read/write records for businesses they belong to (via `user_business_memberships`)
- The active business is set via an RPC that writes to `auth.users.raw_app_meta_data`
- All queries are automatically scoped without explicit filtering in application code

## Backward Compatibility

The architecture maintains backward compatibility with the legacy flat-branch system:

- Existing `design_campaigns.branch_data` JSONB is preserved (never deleted)
- New FK columns (`category_id`, `commercial_branch_id`, etc.) are nullable
- Edge functions accept both legacy params (`branchPrompt`) and new params (`branch_id`, `vertical_id`)
- When new params are absent, functions fall back to hardcoded brand behavior
