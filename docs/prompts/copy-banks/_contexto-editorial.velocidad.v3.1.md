# 2. OBJETIVO EDITORIAL

Comunicar que **Xending es una alternativa ágil y especializada para realizar pagos internacionales que acompañen los tiempos reales de la operación**, especialmente cuando existen:

- proveedores esperando;
- pedidos terminados;
- fechas de producción;
- inventario por reponer;
- refacciones;
- mantenimiento;
- instalaciones;
- proyectos;
- fechas de embarque;
- pagos a China y Asia;
- pagos internacionales que necesitan avanzar con mayor agilidad.

El copy debe explicar **cómo ayuda Xending**.

No debe limitarse a decirle al cliente que se organice, revise, prepare, planee, monitoree o verifique por su cuenta.

La sensación buscada es:

> **El pago puede avanzar al ritmo que necesita mi operación.**

No:

> **Tengo que organizarme mejor para pagar.**

Xending debe aparecer como una **capacidad real para cotizar y realizar el pago**, no como un asesor que únicamente señala la urgencia.

# 5. QUÉ DEBE PENSAR EL CLIENTE

Después de leer una pieza, el cliente debería pensar una o varias de estas ideas:

- Mi pago internacional no necesariamente tiene que tomar varios días.
- Xending puede ayudarme a pagar a mi proveedor con mayor agilidad.
- Si mi proveedor ya terminó el pedido, vale la pena revisar si el pago puede avanzar hoy.
- El pago forma parte del calendario real de mi compra, inventario o producción.
- Pagar a China puede ser mucho más ágil cuando la operación cumple las condiciones aplicables.
- Xending entiende los tiempos de una empresa que importa.
- Una refacción urgente también necesita un proceso de pago ágil.

- Xending puede ser una alternativa especializada para mi siguiente pago internacional.

El cliente **no debe sentirse regañado por no planear con anticipación**.

Debe sentir que Xending le ofrece una forma concreta de hacer avanzar el pago.

# 10. USO DEL CONDICIONAL

El condicional es obligatorio cuando el resultado depende de:

- corredor;
- moneda;
- horario;
- validación;
- banco beneficiario;
- partner;
- disponibilidad operativa;
- terceros.

Preferir:

- puede procesarse;
- puede avanzar;
- puede ayudarte;
- puede realizarse;
- puede recibir, únicamente si esa semántica está confirmada;
- según la operación;
- sujeto a condiciones.

Evitar:

- siempre llega hoy;
- llega inmediatamente;
- nunca se retrasa;
- cualquier pago llega el mismo día;
- pago instantáneo;
- garantizado el mismo día.

## Regla

No utilizar condicional para debilitar una capacidad genérica ya confirmada.

Ejemplo:

> Xending realiza pagos internacionales.

Puede afirmarse si es una capacidad base.

Ejemplo:

> Tu proveedor puede recibir el mismo día.

Solo puede utilizarse si esa semántica específica está confirmada.

# 12. ÁNGULOS EDITORIALES

## 12.1 Pedido terminado

La mercancía ya está lista y el pago es la siguiente acción.

Ejemplo conceptual:

> El pedido está listo. Falta hacer avanzar el pago.

El copy debe centrarse en el pago, no asumir que Xending controla la liberación o salida de mercancía.

## 12.2 Proveedor esperando

La historia se centra en el proveedor y en el siguiente paso de la operación.

Ejemplo conceptual:

> El proveedor está listo. Que el pago también.

No utilizar miedo como:

> Otro cliente avanzará primero.

## 12.3 Mismo día

Existe una capacidad temporal concreta para el corredor y la operación.

Puede utilizar:

- mismo día;
- hoy;
- puede procesarse hoy;

solo cuando la semántica esté confirmada.

La pieza debe incluir el disclaimer aplicable.

## 12.4 Horario aplicable

El momento de recepción puede determinar si una operación alcanza una capacidad de mismo día.

No convertirlo en:

- tutorial;
- clase de husos horarios;
- instrucción para que el cliente se organice.

El beneficio debe seguir siendo una capacidad de Xending.

## 12.5 Continuidad operativa

El pago acompaña:

- compra;
- producción;
- proyecto;
- instalación;
- abastecimiento;
- reposición.

No afirmar causalidad absoluta entre pago y resultado logístico.

## 12.6 Confirmación al proveedor

Una confirmación de pago puede ser relevante para continuar una relación comercial o una siguiente etapa.

Usar únicamente funcionalidades de confirmación o seguimiento realmente disponibles.

## 12.7 Inventario y reposición

El inventario necesita volver a entrar antes de que la disponibilidad se convierta en problema.

El pago es parte de la reposición.

## 12.8 Refacción y mantenimiento

Una pieza crítica puede hacer que el tiempo tenga un valor operacional evidente.

Ejemplo:

> Una refacción urgente también necesita un pago rápido.

La urgencia debe provenir del objeto, no de un titular artificial.

## 12.9 Producción e instalación

Puede aplicarse a:

- maquinaria;
- herramientas;
- iluminación;
- paneles;
- material eléctrico;
- componentes;
- empaques;
- insumos.

La historia debe mostrar qué necesita avanzar.

## 12.10 Fecha de embarque

La fecha de pago puede ser relevante frente al calendario del proveedor o de salida.

No afirmar que Xending controla:

- embarque;
- naviera;
- puerto;
- aduana;
- fecha efectiva de salida.

## 12.11 Temporada y demanda

Aplica cuando un producto tiene una razón real para moverse rápido:

- textiles;
- calzado;
- pantallas;
- electrónicos;
- baterías;
- inventario comercial.

No usar “temporada” si la industria no lo justifica.

## 12.12 Seguimiento y claridad

La rapidez puede acompañarse de:

- estado del pago;
- confirmación;
- soporte;
- acompañamiento.

Solo utilizar capacidades de seguimiento confirmadas.

## 12.13 Especialización China y Asia

Xending puede comunicar una capacidad especializada para China y Asia cuando la infraestructura y los claims estén confirmados.

Puede hablar de:

- proveedor en China;
- pagos a China;
- pagos a Asia;
- mismo día cuando aplique;
- especialización regional.

No utilizar:

> Xending Asia.

## 12.14 Agilidad internacional general

No toda la rama debe hablar de China.

También debe mostrar capacidad para:

- Estados Unidos;
- Europa;
- Asia;
- otros mercados.

Aquí no se promete “mismo día” de manera universal.

Preferir:

- mayor agilidad;
- menos espera;
- tiempos claros;
- acompañamiento.

El producto debe hacer el copy:

- más visual;
- más reconocible;
- más específico;
- más cercano a la operación real.

## Excepción controlada

Una palabra conceptual puede utilizarse cuando:

1. el headline sigue siendo comprensible por sí mismo;
2. la asociación con tiempo o pago es clara;
3. el supporting copy aterriza la situación.

Ejemplo válido:

> Un día de diferencia puede cambiar la operación.

Ejemplo no válido:

> La oportunidad sigue abierta.

No queda claro qué ocurre ni qué está esperando.

# 19. HEADLINE

Debe ser:

- corto;
- claro;
- normalmente de 4–12 palabras;
- puede llegar aproximadamente a 15 si la idea lo necesita;
- entendible sin leer el supporting copy;
- concreto;
- visual;
- empresarial.

Debe contener la tensión temporal principal.

No buscar juegos de palabras si sacrifican claridad.

Preferir:

> **concreto + simple + reconocible**

Ejemplos:

> Pagar a China no debería tomar días.

> La tecnología de pantallas cambia rápido.

> Una refacción urgente también necesita un pago rápido.

# 20. SUPPORTING COPY

Debe:

- ser una sola oración;
- normalmente tener 8–25 palabras;
- explicar o aterrizar;
- añadir información nueva;
- conectar la situación con una capacidad de Xending;
- llevar naturalmente al CTA;
- no repetir el headline;
- no convertirse en tutorial.

Debe responder:

> **¿Cómo ayuda Xending?**

No únicamente:

> **¿Qué debería hacer mejor el cliente?**

Preferir:

> La refacción ya está lista. Falta hacer avanzar el pago.

- qué está listo;

# 28. REGLA DE VARIEDAD Y COBERTURA

No entregar múltiples variaciones de:

> paga rápido.

La diversidad se controla con **cobertura mínima y límites máximos**, no intentando llenar el banco con una sola tesis.

## 28.1 Arquitectura del banco maestro

La estructura de referencia de esta rama es:

- **15 copies GENERALES ANCLA**;
- **30 copies VERTICALIZADOS por producto, industria u operación**.

Los generales enseñan los principales razonamientos temporales de la rama.

Los verticalizados muestran cómo aterrizar esos razonamientos en:

- compras reales;
- productos;
- objetos;
- momentos;
- escenas.

## 28.2 Cobertura mínima de los 15 GENERALES

El bloque de 15 debe cubrir como mínimo:

- 3 copies de pedido terminado / proveedor listo;
- 2 de mismo día;
- 2 de horario / momento del pago;
- 2 de siguiente etapa / continuidad;
- 2 de seguimiento / claridad;
- 1 de inventario;
- 1 de refacción / mantenimiento;
- 1 de China / Asia especializado;
- 1 internacional general.

Los ángulos pueden cruzarse dentro de una misma pieza.

Por eso estos mínimos pueden superponerse.

Los espacios restantes se asignan según calidad y diversidad.

## 28.3 Cobertura de los 30 VERTICALIZADOS

El bloque vertical debe cumplir:

- mínimo 8 verticales distintas;
- mínimo 6 situaciones o ángulos editoriales distintos;
- máximo 5 copies de una misma vertical;
- máximo 6 copies con el mismo ángulo principal;
- máximo 6 copies basados principalmente en “mismo día”;
- máximo 6 copies basados principalmente en “proveedor esperando”;
- máximo 2 copies consecutivos con el mismo ángulo principal;
- máximo 4 usos claros de una misma fórmula narrativa;
- incluir variedad entre producción, inventario, mantenimiento, pedidos, instalación, temporada y reposición.

Estas son reglas de cobertura del **banco maestro y tandas amplias**.

Una campaña deliberadamente monográfica puede usar una distribución distinta si el usuario lo solicita expresamente.

## 28.4 Principio

La meta no es cumplir una fórmula matemática.

La meta es evitar que el banco enseñe al sistema que:

> **velocidad = proveedor esperando + reloj + “paga hoy”.**

# 31. REGLAS ANTI-REPETICIÓN

Aplican al banco maestro y a tandas amplias.

## Ángulo

- no más de 2 copies consecutivos con el mismo ángulo principal;
- ningún ángulo principal debe superar 6 de los 30 verticalizados;
- máximo 6 verticalizados principalmente sobre “mismo día”;
- máximo 6 principalmente sobre “proveedor esperando”;
- los 15 generales deben cubrir varios territorios y no concentrarse en una sola tesis.

## Fórmula narrativa

- no utilizar claramente la misma fórmula narrativa más de 4 veces dentro de una tanda de 30;
- “X está listo. Que el pago también” máximo 2 veces por tanda;
- no abusar de “no debería esperar”;
- no repetir “mantén tu operación en movimiento” como supporting comodín.

## Apertura del headline

En los 15 generales:

- máximo 3 headlines pueden empezar con la misma primera palabra o construcción.

En los 30 verticalizados:

- máximo 6 headlines pueden empezar con la misma primera palabra o construcción.

Evitar especialmente la repetición automática de:

- El...
- La...
- Tu...
- Cada...
- Hoy...

## Léxico

Evitar repetir excesivamente:

- pago;
- proveedor;
- rápido;
- hoy;
- mismo día;
- operación;
- avanzar;

cuando exista otra historia concreta.

La solución no es buscar sinónimos artificiales.

La solución es **cambiar la situación, el objeto o el momento**.

# 32. RELACIÓN HEADLINE → SUPPORTING COPY → CTA

Cada elemento cumple una función diferente.

## Headline

Genera atención.

## Supporting copy

Explica la consecuencia temporal y la capacidad de Xending.

## CTA

Ofrece una acción concreta.

### Correcto

**Headline:** Pagar a China no debería tomar días.

**Supporting copy:** Con Xending, tu pago puede procesarse el mismo día cuando aplican las condiciones correspondientes.

**CTA:** Paga a China hoy.

### Correcto

**Headline:** Una refacción urgente también necesita un pago rápido.

**Supporting copy:** Xending te ayuda a pagar al proveedor con mayor agilidad cuando el tiempo de reposición importa.

**CTA:** Cotiza tu próximo pago.

### Incorrecto

**Headline:** Revisa tus horarios.

**Supporting copy:** Revisa la hora antes de realizar la transferencia.

**CTA:** Prepara tu pago.

El ejemplo incorrecto asigna toda la responsabilidad al cliente y Xending no aparece como capacidad.

# 33. REGLAS DE NEGOCIO DURAS

## Naturaleza de Xending

Xending **NO es banco**.

Xending es una **plataforma de pagos internacionales**.

Xending tampoco debe presentarse como empresa de logística.

## Resultado logístico

No afirmar que Xending controla:

- embarques;
- aduanas;
- producción;
- inventario;
- navieras;
- prioridades del proveedor;
- fecha de salida efectiva.

El pago puede ayudar a que una operación avance.

No garantiza el resultado logístico posterior.

## Semántica de “mismo día”

Distinguir siempre:

```text
SAME_DAY_PROCESSING
≠
SAME_DAY_PAYMENT_SENT
≠
SAME_DAY_SETTLEMENT
≠
SAME_DAY_BENEFICIARY_CREDIT
```

El agente nunca puede transformar una semántica en otra para hacer el copy más atractivo.

Ejemplo:

> Tu pago puede procesarse el mismo día.

NO equivale automáticamente a:

> Tu proveedor recibe el mismo día.

## Fuente operativa

Todo claim temporal específico debe estar respaldado por una fuente vigente de Producto / Operaciones que defina, como mínimo:

- corredor;
- moneda;
- país destino;
- semántica del claim;
- horario límite cuando aplique;
- zona horaria;
- días hábiles;
- wording aprobado;
- CTA aprobado;
- disclaimer;
- estado vigente.

El banco creativo no sustituye esa fuente.

## Mismo día

No generalizar “mismo día” a todos los corredores.

No utilizar:

- instantáneo;
- inmediato;
- siempre llega hoy;
- cualquier pago llega hoy;
- 24/7;
- garantizado;

salvo capacidad factual expresamente autorizada.

## China / Asia

No utilizar:

> Xending Asia.

No afirmar presencia física propia de Xending en Asia salvo confirmación expresa.

No afirmar:

- ruta directa;
- sin intermediarios;
- la ruta más rápida;
- más rápido que los bancos;

sin evidencia y aprobación.

## Seguimiento

Solo utilizar afirmaciones de:

- tracking;
- seguimiento;
- estado;
- trazabilidad;

si la funcionalidad está confirmada.

## Partners

No atribuir una capacidad, tiempo o claim a un partner si no está aprobado para comunicación comercial.

## CTA “Paga sin demoras a tu proveedor”

Puede conservarse como **construcción editorial aprobada**, pero contiene un absoluto implícito.

No debe generarse libremente por analogía.

Su publicación debe seguir la validación definida en este documento.

- tiempo documentado por corredor;
- fecha concreta que proviene del brief del usuario;

- fuente operativa vigente;
- corredor;
- moneda cuando corresponda;
- zona horaria cuando aplique;
- semántica correcta del claim;
- validación de producto;
- validación legal cuando corresponda.

## Prohibido

- tiempos inventados;
- “2–5 días” contra bancos sin evidencia;
- porcentajes de reducción de tiempo no demostrados;
- 24/7 sin confirmación;
- instantáneo;
- horas de corte promocionales inventadas.

## Cuota creativa de cifras

Para cifras ilustrativas que NO sean simplemente capacidades operativas confirmadas:

- tandas de 1 a 20 copies: máximo 1;
- tandas de 21 a 40: máximo 2;
- banco maestro de 45: máximo 2.

Es un techo, no un objetivo.

El banco maestro puede contener cero cifras arbitrarias.

## Principio

> **En Velocidad, un número temporal no es decoración. Es un claim.**

# 43. SEMÁNTICA DEL CAMPO VALIDACIÓN

El campo **Validación** indica si el copy puede pasar directamente al banco aprobado o necesita una revisión adicional.

## `OK`

Usar cuando:

- el copy permanece dentro de capacidades base ya confirmadas;
- no contiene un claim temporal sensible;
- no contiene una comparación que requiera revisión;
- no depende de una funcionalidad específica pendiente de confirmar.

## `REQUIERE_VALIDACIÓN_PRODUCTO`

Usar cuando el copy depende de una capacidad específica que debe comprobarse, por ejemplo:

- corredor;
- país;
- moneda;
- tiempo de procesamiento;
- tiempo de acreditación;
- hora límite;
- seguimiento;
- partner;
- funcionalidad operativa.

## `REQUIERE_VALIDACIÓN_LEGAL`

Usar cuando:

- introduce una construcción nueva de “mismo día”;
- utiliza un claim sensible;
- utiliza una comparación temporal;
- contiene un absoluto aprobado solo bajo ciertas condiciones;
- necesita disclaimer o tratamiento legal específico.

Una construcción exacta previamente aprobada puede reutilizarse bajo la política interna correspondiente.

## `REQUIERE_VALIDACIÓN_PRODUCTO_Y_LEGAL`

Usar cuando aplican simultáneamente ambos tipos de revisión.

Ejemplo:

> una construcción nueva que afirma pago a China el mismo día y además depende de confirmar el corredor.

## Regla

No marcar `OK` por defecto.

La validación debe ser el resultado de revisar el contenido real del copy.

# 47. PRINCIPIO FINAL

La esencia de esta rama es:

> **El tiempo importa porque algo real está esperando el pago.**

Xending debe presentarse como:

> **una alternativa ágil, clara y especializada para realizar pagos internacionales que acompañen el ritmo real de la operación.**

El banco maestro debe enseñar esta idea mediante ejemplos diversos, concretos y visuales.

No debe enseñar una sola fórmula dominante.

No debe convertir velocidad en:

- presión;
- miedo;
- logística;
- tutorial;
- promesa absoluta.

Debe enseñar al sistema que la velocidad se entiende mejor cuando existe:

> **un proveedor, un pedido, una fecha, una refacción, un inventario, una máquina o un proyecto que necesita que el pago avance.**

Ese es el territorio.

Todo copy de esta rama debe permanecer dentro de él.
