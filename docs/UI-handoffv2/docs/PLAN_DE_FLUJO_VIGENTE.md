**Fuente:** documento de Fai suministrado en esta conversación después del handoff v1. Se conserva su organización y sus decisiones de producto.
**Uso en v2:** especificación de la propuesta visual; no declaración de implementación ni autorización automática para ejecutar todo el plan. Las aclaraciones posteriores sobre iconos exactos y conversación se recogen en `DISENO_MAESTRO.md`.

## 1. Tu tarea

Usa el PDF del flujo de ScoryDesign y las referencias visuales aprobadas que están en este chat para generar imágenes de la nueva interfaz, incorporando este plan.

La entrega es una propuesta visual completa y coherente. No implementes la aplicación ni sustituyas su funcionamiento.

Si no tienes el PDF o las imágenes aprobadas, pide esas referencias antes de inventar otra dirección visual.

Este documento actualiza las decisiones de producto. Los textos ilustrativos dentro de las imágenes anteriores no deben convertirse automáticamente en requisitos funcionales.

## 2. Referencias y prioridades

- **Código y capacidades actuales:** determinan lo que se reutiliza y debe conservarse. El inventario de este documento resume lo verificado por el usuario.
- **PDF existente:** conserva la lógica del recorrido, sus alternativas y la continuidad. Sus 21 vistas no son 21 pasos obligatorios.
- **Diseño e imágenes aprobadas:** determinan la apariencia.
- **Este plan:** actualiza entradas, alcance, estilos por marca y estrategia de migración.

Si hay discrepancias, explica cómo las resuelves. No presentes una función propuesta como si ya estuviera implementada.

La dirección visual documentada es clara/cobalto: blanco mineral, tinta azul oscura, profundidad discreta, iconos cuidados y espacio para el contenido. Si en este chat existe una aprobación visual posterior, úsala e identifica esa referencia.

Evita una barra lateral genérica cargada de herramientas, formularios interminables y pantallas saturadas. Mantén una familia visual consistente en todas las imágenes.

## 3. Objetivo y estrategia

La creación actual se reutiliza completa:

- Llamadas y procesos existentes.
- Prompts y reglas de generación.
- Ideas y propuestas de copy.
- Banco actual y copys anteriores.

La nueva UI mejora el recorrido y conecta las capacidades existentes. El chat, los botones y los campos operan sobre el mismo trabajo.

Convivirán:

1. **Studio actual:** conserva su proceso y ambos bancos de copys.
2. **Xending News y Daily Report:** siguen aparte, con sus estructuras y formatos actuales.
3. **Nuevo espacio “Crear y editar”:** estrena la nueva UI y permite completar el trabajo desde distintos puntos de partida.

Después de revisar recorridos reales con la nueva UI, se migra gradualmente el resto.

Una portada de LinkedIn es un caso de validación; el alcance del espacio incluye también presentaciones, imágenes, páginas y carruseles.

## 4. Tres puntos de partida

| Entrada | Comportamiento |
|---|---|
| Crear desde cero | Describir la intención y completar las decisiones faltantes |
| Usar una plantilla | Elegir una base compatible y personalizarla |
| Partir de un diseño existente | Recuperar un trabajo, pulirlo o usarlo como base para una variante |

Estas entradas deben servir para los distintos tipos de pieza.

No obligar a quien ya trae copy, estilo, prompt o diseño a repetir toda la preparación.

Distinguir:

- **Continuar editando:** abrir el trabajo existente.
- **Usar como base:** conservar el original y crear otra pieza o versión.

El origen y el tipo de pieza son decisiones independientes. Una portada, presentación o carrusel puede comenzar desde cero, una plantilla o un diseño existente.

## 6. Marca y estilos aprobados

Crear desde cero para Xending conserva sus estándares.

Los estilos actuales se reutilizan con sus reglas y prompts:

- Blanco V1.
- Blanco Xending V2.
- Blanco Xending V3.
- Blanco 2.0.
- Navy.

No necesitan una nueva aprobación por cambiar la interfaz.

El selector debe mostrar:

- Nombre del estilo.
- Ejemplo visual.
- Usos compatibles.
- Estilo seleccionado.

Un estilo incluye composición, tipografía, tratamiento de imagen, CTA y reglas de marca, además de colores.

Reglas:

- Mantener marca y estilo visibles durante el trabajo.
- Aplicarlos al generar, editar, regenerar y retomar.
- Conservar la versión de estilo utilizada.
- Evitar opciones incompatibles con el estilo elegido.
- No sustituir estilos ausentes por los de otra marca.
- Una actualización del estilo no cambia automáticamente trabajos anteriores.

Para una dirección nueva:

**Referencias → Propuesta → Revisión → Aprobación → Estilo disponible.**

Ya existe configuración de marca y revisión de una dirección visual. El catálogo de varios estilos aprobados por marca, compartido entre herramientas, es una integración que falta completar.

Distinguir:

- Aprobación de estilo.
- Aprobación de copy.
- Aprobación de resultado.

Aprobar una imagen no la convierte automáticamente en un estilo reutilizable.

Xending es una marca de servicios financieros y pagos internacionales. Un ejemplo con cables representa contenido sobre una industria cliente; no convierte a Xending en fabricante.

Conservar identidad y logos reales.

## 7. Flujo adaptable

| Momento | Interacción | Reutilización |
|---|---|---|
| Empezar | Nuevo, plantilla o diseño existente | Bibliotecas, proyectos y documentos |
| Definir pieza | Tipo y formato de destino | Catálogos y herramientas actuales |
| Preparar contenido | Escribir, elegir copy, corregir o pedir propuestas | Bancos, generación de propuestas y contexto de marca |
| Preparar diseño | Estilo, tipo de imagen, referencias y prompt | Prompts y reglas existentes |
| Crear y ajustar | Generar, editar y comparar | Generadores, editores y revisión actual |
| Terminar y continuar | Versiones, marca, exportación, guardado y reapertura | Persistencia y procesos actuales |

Son momentos accesibles, no un asistente rígido:

- Con una idea, ayudar a completar lo necesario.
- Con copy y estilo, continuar desde la preparación.
- Con prompt vigente, revisar y generar.
- Con imágenes terminadas, entrar directamente a resultados.
- Con un documento existente, abrir su edición compatible.

Distinguir preparación de generación.

No generar variantes sólo para llenar tarjetas del resumen.

La acción principal debe estar junto a sus controles y explicar qué ejecutará:

- Generar imagen.
- Generar lámina.
- Generar pendientes.
- Actualizar composición.
- Guardar versión.

## 16. Reglas visuales y de entrega

- Una imagen legible por vista.
- Evitar un collage diminuto como única entrega.
- Mantener continuidad entre pantallas.
- Usar ejemplos consistentes.
- Usar español claro y contenido concreto.
- Diferenciar estilo de la plataforma y estilo de la pieza.
- Mostrar estados de carga, error, cambios pendientes y guardado.
- No marcar automáticamente todo como aprobado.
- No inventar notificaciones, métricas, proyectos ni funciones para decorar.
- No meter explicaciones técnicas o números de lámina dentro de la UI.
- Colocar las explicaciones de revisión fuera de la interfaz.
- Explicar qué se reutiliza y qué conexión nueva se propone.
- Presentar las imágenes como propuestas visuales, no como capturas de una aplicación implementada.
- Entregar imágenes visibles en el chat.
- Entregar también archivos PNG numerados con nombres claros.

Si este chat tiene acceso autorizado a la Biblioteca de ScoryDesign, guardar allí las propuestas bajo Xending y verificar el resultado.

Si no tiene acceso, entregar los archivos y declarar el guardado pendiente.

No confundir la Biblioteca de ScoryDesign con la biblioteca de ChatGPT.

## 17. Criterio de revisión

La serie debe permitir entender tres recorridos completos:

### Recorrido A: desde cero

Idea → Contenido → Estilo aprobado → Preparar → Generar → Corregir → Guardar → Retomar.

### Recorrido B: desde plantilla

Elegir plantilla → Personalizar → Revisar → Guardar o exportar.

### Recorrido C: desde diseño existente

Abrir diseño → Continuar o crear variante → Pulir → Guardar → Reabrir.

Incluir imagen, portada, presentación y carrusel.

La propuesta debe permitir reconocer el producto actual y sus capacidades, con una organización más limpia y continuidad entre herramientas.

El criterio de éxito es poder empezar, generar, corregir, guardar y retomar un trabajo completo usando la nueva UI y reutilizando los procesos existentes.
